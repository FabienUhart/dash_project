# Format d'export — historique des versions v1 → v28

> Détail par version de l'**invariant 1** de `CLAUDE.md` (compat ascendante des sauvegardes). Déplacé ici le 30 sept. 2026 pour alléger le contexte de session ; `CLAUDE.md` garde la règle et l'index. **À chaque bump de format** : une entrée ici + l'index de `CLAUDE.md` + `APP_VERSION`.

`/api/import` doit toujours accepter les exports :

- v1 (liens seuls)
- v2 (+ catégories/mémos)
- v3 (+ uid/dates)
- v4 (+ done/due_date/priority/subtasks sur les mémos, color sur les catégories)
- v5 (+ projets de mémos, rattachés par nom)
- v6 (+ images sur les mémos, noms de fichiers seulement)
- v7 (+ tags sur les liens, normalisés minuscules sans #)
- v8 (+ tags sur les projets)
- v9 (+ `recurrence` sur les mémos et liste `history` des tâches effectuées, dédupliquée par (memo_uid, done_at))
- v10 (+ liste `priorities` ; `memos.priority` est remappé par NOM de priorité à l'import, jamais par id brut)
- v11 (+ `emoji` sur catégories, projets et mémos)
- v12 (+ `parent` sur les projets, résolu par NOM en deux passes à l'import, jamais par id)
- v13 (+ `location` JSON {lat, lng, label} sur mémos et projets, validée par `_clean_location()` — coordonnées bornées, jamais de HTML)
- v14 (+ `title` et `assignees` (liste de noms libres, dédupliquée, nettoyée par `_assignees_json()`) sur les mémos, `description` sur les projets, liste `comments` à la racine — rattachés par `memo_uid`, dédupliqués par (memo_uid, created_at, author) ; un mémo peut avoir un titre SANS contenu : la validation est « titre OU contenu », et la dédup sans uid utilise le titre quand le contenu est vide)
- v15 (+ `priority` (0-3) et `parent_created_at` sur les `comments` — le `parent_id` est résolu à l'import en rattachant le commentaire dont le (memo_uid, created_at) correspond, donc les réponses survivent ; les mémos en corbeille — `deleted_at` non vide — sont **exclus** de l'export ; le statut « vu » (`comment_seen`) n'est PAS exporté)
- v16 (+ `marker_color` sur les mémos ET les projets — couleur perso du point sur la carte, validée par `_clean_hex_color()` → `#rrggbb` strict ou `''`, jamais de HTML ; `''` = pas d'override, on retombe sur priorité/projet/défaut, ce qui garantit la compat ascendante : tous les exports v1→v15 sans le champ rendent à l'identique ; côté partage, l'override est exposé sous la clef `point_color` pour ne pas le confondre avec le `marker_color` global = couleur par défaut de la carte)
- v17 (+ `map_groups` sur les mémos — liste JSON d'étiquettes de groupe de carte, nettoyée/dédupliquée par `_map_groups_json()` comme `assignees`, max 30, jamais de HTML ; absent = `[]`, garantit la compat ascendante v1→v16 ; pas de table séparée : un groupe est « par projet » car on ne le voit que parmi les points du projet courant sur la carte)
- v18 (+ `due_time` sur les mémos — heure optionnelle `"HH:mm"` 24 h ou `''`, validée par `_clean_due_time()` (regex stricte → `''` sinon, jamais de HTML) ; dépend de `due_date` : une heure sans date n'existe pas, et vider la date vide l'heure ; absent = `''`, garantit la compat ascendante v1→v17 ; upsert non destructif comme `marker_color` — newer-wins n'écrase jamais une heure présente par une absente/plus ancienne ; émis automatiquement via `_memo_dict`)
- v19 (+ `created_by` sur les mémos — identité du créateur : `''` = le propriétaire (résolu à l'affichage via `_owner_name(db)` → `created_by_display`, survit au renommage owner, comme l'auteur `moi` des commentaires), chaîne non vide = invité « Nom <email> » posée à la création via `/share/<token>/memos` ; absent à l'import = `''`, garantit la compat ascendante v1→v18 ; upsert non destructif (newer-wins n'écrase jamais un `created_by` non vide par un vide/plus ancien) ; `created_by_display` est runtime-only, **jamais exporté** — seul `created_by` brut l'est ; **owner-only** : non exposé aux invités dans `_share_memo_dict` qui n'expose que `created_at`)
- v20 (+ `is_trip` sur les projets — flag « voyage » héritable [MAP-TIMELINE] : `NULL` = hérite du plus proche ancêtre tranché, `1` = voyage, `0` = non, défaut résolu = pas voyage via `_resolve_trip()` ; exporté **BRUT** (null/0/1, jamais résolu) ; absent à l'import (v1→v19) = `NULL` = hérite → rendu identique, compat ascendante garantie ; **upsert non destructif** : un `0/1` local n'est JAMAIS écrasé — ni par un absent/NULL, ni par une autre valeur, seul un existant `NULL` s'enrichit ; côté invités, `share_data`/hub `/data` exposent uniquement le booléen **`trip` RÉSOLU par le serveur** (l'arbre du partage peut être tronqué au scope), **lecture seule** — le flag n'est PAS éditable via `/share`, même `can_edit`)
- v21 (+ `reactions` sur les `comments` — réactions emoji [COMMENT-REACTIONS] : liste JSON `[{emoji, voter, created_at}]` par commentaire, table additive `comment_reactions (comment_id, emoji, voter, created_at, UNIQUE(comment_id, emoji, voter))`, `CREATE TABLE IF NOT EXISTS` — jamais destructive ; **palette CONFIGURABLE** [REACTION-PALETTE] : whitelist serveur data-driven `_reaction_palette(db)` (config owner dans `app_state.reaction_emojis`, seed = 6 base `REACTION_EMOJIS = 👍 👎 ❤️ 😂 😮 🎉`, l'owner **ajoute/retire**), la réaction est validée contre cette palette (tout autre → 400) ; **ajout d'emoji validé STRICTEMENT** par `_clean_reaction_emoji` (un seul grapheme emoji, Python pur — plages Unicode + accessoires ZWJ/VS/teinte/keycap/régionaux + garde ≤ 10 cp, zéro lib/CDN — invariant 6 ; rejette texte/HTML/2-emojis → 400) ; palette **exportée avec les réglages** (top-level `reaction_emojis`, émise seulement si custom → compat v20/v21 sans palette = base par défaut, aucun crash ; import restauré si aucune config locale, non destructif) ; **votant** = pattern `created_by` — `voter=''` = propriétaire (résolu à l'affichage via `_owner_name` → `voters`/`mine`, survit au renommage, comme `created_by`), non vide = invité « Nom <email> » ; **toggle** par (commentaire, emoji, votant) via `UNIQUE(...)` ; exporté **BRUT** (`voter` verbatim, jamais résolu), absent à l'import (v1→v20) = aucune réaction = rendu identique, compat ascendante garantie ; import **additif non destructif** : `INSERT OR IGNORE` sur la clé unique (ré-import v21 = 0 doublon), commentaire résolu par (memo_uid, created_at, author), emoji hors palette ignoré ; **purge en cascade** (suppression commentaire + purge définitive mémo suppriment les réactions AVANT les commentaires) ; côté invités, réagir exige un invité **approuvé** mais **PAS `can_edit`** (réagir ≠ éditer) via `POST /share/<token>/comment/<id>/react` (scope revalidé, invariant 5), `voters` expose le **nom seul** (e-mail owner-only) ; les réactions **ne comptent pas** dans le badge d'activité 🔔 ; `comment_seen` reste non exporté)
- v22 (+ `attachments` sur les mémos — pièces jointes de TOUT type [ATTACHMENTS] : liste JSON `[{filename, orig_name, mime, size, preview, created_at, created_by}]` par mémo, table additive `attachments (id, memo_id, memo_uid, filename, orig_name, mime, size, preview, created_at, created_by, share_id)`, `CREATE TABLE IF NOT EXISTS` — distincte de `memos.images` (photos EXIF/carte, inchangées) ; **binaire jamais dans le JSON**, noms de fichiers seuls (comme les images) — les fichiers vivent dans `data/uploads/` ; **`preview`** = type « aperçu sûr » (image/pdf/audio validé par SIGNATURE binaire) → aperçu inline possible, **tout le reste = téléchargement forcé** (`Content-Disposition: attachment`, jamais inline — anti-XSS, aucun HTML/SVG/script rendu) ; **`created_by`** = pattern `created_by` v19 (`''` = owner, sinon « Nom <email> » pour un upload invité) ; export **BRUT** (voter/filenames verbatim), absent à l'import (v1→v21) = aucune pièce jointe = rendu identique, compat ascendante garantie ; import **additif non destructif** : n'ajoute que les fichiers dont le **binaire EXISTE** sur le volume (tolérant comme les références d'image orphelines) et pas déjà rattachés (dédup par (memo_id, filename)) — ré-import = 0 doublon ; **purge en cascade** (`_purge_memo_row` supprime fichiers + lignes) ; taille max **300 Mo/fichier** (`MAX_CONTENT_LENGTH` = 320 Mo, gunicorn `--timeout 300`) ; côté invités, upload sous **`/share/<token>/memo/<id>/attachments`** (bypass Authelia, invariant 5 — invité **approuvé + `can_edit`** requis, scope revalidé) et download `/share/<token>/attachment/<id>` (tout invité ayant accès, scope revalidé) ; owner `/api/memos/<id>/attachments` + `/api/attachments/<id>` (derrière Authelia))
- v23 (+ `attachments` sur les **projets** [FOLDER-ATTACHMENTS] — une pièce jointe peut viser un DOSSIER au lieu d'un mémo : colonne additive `attachments.project_id` (nullable ; rempli = attache de dossier avec `memo_id = 0` puisqu'aucun mémo n'a l'id 0 → invisible des requêtes mémo `WHERE memo_id = ?` ; NULL = attache de mémo v22 inchangée), même stockage `data/uploads/` (noms de fichiers seuls dans le JSON, jamais le binaire), même validation par signature et même service inline/download anti-XSS que les mémos ; **export niché par projet** (clef `attachments` dans chaque entrée de `projects`, rattachée par NOM à l'import comme le reste d'un projet), absent à l'import (v1→v22) = aucune pièce jointe de dossier = rendu identique, compat ascendante garantie ; import **additif non destructif** (`_import_project_attachments` : binaire présent + dédup `(project_id, filename)`, ré-import = 0 doublon) ; **purge en cascade** à la suppression du dossier (`delete_project` supprime fichiers + lignes) ; routes owner `GET/POST /api/projects/<id>/attachments` (derrière Authelia) et invité `POST /share/<token>/project/<id>/attachments` (bypass `/share/*`, **partage de projet uniquement**, dossier dans le sous-arbre autorisé, invité **approuvé + `can_edit`**, scope revalidé — invariant 5) ; download/delete réutilisent `GET`/`DELETE /api/attachments/<id>` (owner) et `/share/<token>/attachment/<id>` (invité, scope élargi par `_attach_in_share_scope` = mémo dans le scope OU dossier descendant d'un partage de projet). **[FILES-VIEW]** ajoute des vues de recherche (agrégation `_collect_files` : fichiers de dossier + de mémo + images legacy avec **fil d'Ariane cliquable** `source`) — routes **lecture** owner `GET /api/projects/<id>/files?subtree=1` + global `GET /api/files`, invité `GET /share/<token>/project/<id>/files` (borné au sous-arbre du token) — **données dérivées, RIEN de nouveau dans l'export**)
- **v24** (+ `due_end` sur les mémos [MEMO-DATE-RANGE] — **date de FIN** de plage `YYYY-MM-DD` ou `''` : hôtels multi-nuits, événements multi-jours. **PREMIER bump depuis v23** : `due_end` est une **donnée utilisateur réelle EXPORTÉE** (≠ `end_time`/voix qui restent non exportés). Validée `_clean_due_end()` (regex stricte → `''`, jamais de HTML) + garde-fous : exige `due_date`, `due_end ≥ due_date`, **exclusive de la récurrence** (400 explicite côté écriture ; effacer la date efface la fin). Absente à l'import (v1→v23) = `''` = mémo mono-jour → **rendu identique, compat ascendante garantie** (invariant 2). Import **tolérant** (une fin invalide — sans date, < début, ou avec récurrence — est ignorée, jamais de 400) et **non destructif** (une fin présente n'est pas écrasée par une absente). Émise via `_memo_dict` ; exposée aux invités (`_share_memo_dict`), éditable selon la matrice de rôles ([GUEST-ROLES]). UI : champ « → fin » dans la pop-in (3 pages, visible si date posée et pas de récurrence), badge « 3 → 6 nov » sur cards/plan/agenda, « En retard » basé sur la **fin effective** (un séjour en cours n'est pas en retard), agenda/frise voyage : le mémo couvre **chaque jour** de sa plage (point carte UNIQUE). `APP_VERSION="24"`)
- **v25** (+ `uid`/`parent_uid` sur les projets et `project_uid` sur les mémos [PROJECT-NAME-PER-FOLDER] — **unicité des noms de dossiers PAR DOSSIER PARENT** (plus globale) : deux dossiers de même nom ne peuvent être **frères** (même `parent_id`, racine incluse, `COALESCE(parent_id,0)` — les NULL SQLite sont distincts), mais « restaurants » sous « Japon » ET sous « Corée » est désormais possible. Le nom n'étant plus une clef fiable, chaque projet porte un **`uid` stable** (invariant 3, backfillé par `init_db()`, jamais régénéré) via un **rebuild de la table `projects`** (SQLite ne retire pas un UNIQUE : rename → create sans UNIQUE(name) → port en préservant les `id` → `CREATE UNIQUE INDEX ux_projects_name_parent`, idempotent). **Résolution import UID-D'ABORD** puis par **(nom, parent résolu)** — plus jamais par nom à plat : création **topologique** (parent résolu AVANT l'insert → aucune collision « tout à la racine ») ; les mémos rattachés par `project_uid` puis `project` (nom). Absents à l'import (v1→v24) = résolution (nom, parent) : les vieux exports avaient des noms globalement uniques → chemin toujours résolvable → **rendu identique, compat ascendante garantie** (invariant 2). Upsert par uid **non destructif** : le nom LOCAL n'est **jamais écrasé** (les projets n'ont pas d'`updated_at` → « newer-wins » indécidable, on ne détruit pas un renommage local) ; ré-import d'un export v25 = **0 ajout, 0 doublon**. `name`/`parent` (nom) **restent émis** (lisibilité + compat). **Collision au DÉPLACEMENT (D4)** owner comme invité → **409** « un dossier de ce nom existe déjà à cet endroit » (jamais de 500), garde unique `_sibling_name_taken`. [EXPORT-SUBTREE] doublé de `proj_uids`/`project_uid` ; « Importer ici » évalue « racine nouvelle » par uid-puis-chemin. Provisioning d'espace invité et suffixe de dédup **re-scopés au parent**. `APP_VERSION="25"`)
- **v26** (+ `created_by` sur les **projets** [GUEST-HOME] — identité du créateur d'un dossier : `''` = le propriétaire, chaîne non vide = invité « Nom <email> » (dossier perso). **Donnée utilisateur réelle désormais EXPORTÉE** : sans elle, après restauration sur base neuve, la dédup GLOBALE par e-mail et l'élévation par propriété (`_owns_guest_space_folder`) seraient perdues → une ré-approbation créerait un espace **dupliqué**. Import : restaure `created_by` (résolution **uid-d'abord** comme v25) — **création** (INSERT direct) et **enrichissement non destructif** (n'écrit que si l'existant est vide, jamais d'écrasement). Absent à l'import (v1→v25) = `''` → **rendu identique, compat ascendante garantie** (invariant 2). Les partages/`share_guests` restent NON exportés (secrets) : après restauration, une ré-approbation **raccroche** l'espace existant via la dédup `created_by`. `APP_VERSION="26"`)
- **v27** (+ liste top-level `memo_links` — **liens symétriques entre mémos** [MEMO-LINKS] : table additive `memo_links (src_memo_id, dst_memo_id, created_at, created_by)`, `CREATE TABLE IF NOT EXISTS` — jamais destructive ; **une seule ligne par paire NON ORDONNÉE** (index unique sur `CASE WHEN src<dst…`, déterministe) : le lien est **symétrique en effet** (visible/suivable des deux côtés) mais **orienté en mémoire** (`src` = le mémo depuis lequel il a été posé, pilote le style des chips) ; auto-lien **400**, plafond **20 liens/mémo** (400 explicite), `created_by` = pattern v19 (`''` = owner, sinon « Nom <email> ») ; mémo en **corbeille** → ses liens sont **masqués partout mais conservés** (restauration = ils reviennent), **purge définitive** → liens supprimés en cascade (`_purge_memo_row` + `_purge_trash`). Exporté **par UID** (`[{src_uid, dst_uid, created_at, created_by}]`, jamais d'id) et borné aux mémos exportés (sous-arbre [EXPORT-SUBTREE] inclus) ; import **uid-d'abord TOLÉRANT** (uid inconnu → lien ignoré, jamais de 400), **dédup par paire non ordonnée** (ré-import v27 = 0 doublon), **additif non destructif** (un lien local n'est jamais retiré). Absent à l'import (v1→v26) = aucun lien = **rendu identique, compat ascendante garantie** (invariant 2). Le champ `links` des payloads mémo est **runtime-only, JAMAIS exporté** (comme `created_by_display`) et **borné au scope du lecteur** — un lien vers un mémo hors scope d'un invité est **omis** (jamais de titre-fantôme, invariant 5). `APP_VERSION="27"`)
- **v28** (+ liste top-level `link_refs` — **un LIEN relié à un mémo ou à un DOSSIER** [LINK-REFS] : table additive `link_refs (id, link_id, kind CHECK IN ('memo','project'), target_id, created_at, created_by, UNIQUE(link_id, kind, target_id))`, `CREATE TABLE IF NOT EXISTS` — jamais destructive ; la relation est **orientée en base** (le lien la porte) mais **se lit des deux côtés** (chips 🔗 sur la card du mémo et sur le board du dossier, chips 📝/📁 sur la card du lien) ; plafond **20 par lien ET par cible** (400 explicite), cible inexistante ou **en corbeille** → 404, `created_by` = pattern v19 (`''` = owner) ; mémo en **corbeille** → ses relations sont **masquées partout mais conservées** (restauration = elles reviennent), **purge définitive** / suppression du lien / suppression du dossier → relations supprimées en cascade. Exporté **par UID** (`[{link_uid, kind, target_uid, created_at, created_by}]`, jamais d'id) et **borné aux objets exportés** (sous-arbre [EXPORT-SUBTREE] inclus : une relation vers un lien/mémo/dossier hors périmètre est **omise**, sinon l'export porterait un uid que rien dans ce fichier ne résout) ; import **uid-d'abord TOLÉRANT** (uid inconnu → relation ignorée, jamais de 400), `INSERT OR IGNORE` sur la clé unique (ré-import v28 = 0 doublon), **additif non destructif** (une relation locale n'est jamais retirée), compteur `imported_link_refs`. Absent à l'import (v1→v27) = aucune relation = **rendu identique, compat ascendante garantie** (invariant 2). Les champs `refs` (côté lien) et `link_refs` (côté mémo/dossier) des payloads sont **runtime-only, JAMAIS exportés** (comme `links` de v27). **Invités : exposition CONSENTIE, en LECTURE SEULE** — relier un lien à un mémo ou un dossier partagé est un acte du propriétaire, donc son consentement à le montrer : `_share_memo_dict`/hub portent une **projection STRICTE `{name, url_public, og_domain}`** et rien d'autre (jamais `url_local`, jamais la note `memo`, jamais les tags, jamais d'id/uid — la table `links` reste hors périmètre) ; un lien **sans `url_public` n'est pas exposé du tout** (un service du LAN n'a rien à faire chez un invité) ; **aucune route `/share/*` nouvelle** (invariant 5) et aucune écriture invitée, même `can_edit`. `APP_VERSION="28"`).

Toute évolution du format incrémente `version` dans l'export et reste importable.
