  - **Mentions `@`** : blot Quill `mention` (`<span class="mention" data-mention>`) + menu d'autocomplétion dans l'éditeur ET dans le champ commentaire (`attachInputMention`). Sélection = insère `@Nom` + ajoute aux assignés. Source = `assigneeSuggestions()` / `shareSuggestions()` (toi + invités + noms déjà utilisés, saisie libre). La pop-in « Modifier le mémo » de la page partagée a enfin un champ assignés général (`#q-people`) + un titre (`#q-title`).
  - **Signal d'accès** : un assigné/mention qui n'a pas accès au partage s'affiche en **ambre `⚠ @Nom`** (badge, puce, mention inline). Dashboard : accès = propriétaire ou invité approuvé d'un partage couvrant le projet du mémo (ou un ancêtre). Partage : accès = `DATA.members`.
  - **Corbeille** (invariant 7) : `memos.deleted_at`, vue 🗑 sidebar (Restaurer / Supprimer définitivement / Vider), purge auto 7 j (`_purge_trash`). Côté partage, l'invité approuvé peut supprimer (→ corbeille) et restaurer (tuile 🗑 ; `trash` dans `share_data`, routes `DELETE`/`POST .../restore` et `.../seen`).
  - **Ouvrir un projet à un invité existant** depuis 🔗 Partages : `POST /api/guests/grant` (réutilise un partage projet aux mêmes droits sinon en crée un, pré-approuve l'invité, renvoie lien+PIN).
  - **Favicon** `static/favicon.svg` (whitelisté partage). **Dupliquer un mémo** `POST /api/memos/<id>/duplicate` (copie tout sauf images, `done` remis à 0, titre + « (copie) »). Supprimer/Dupliquer déplacés dans un **menu ⋯** en haut de la pop-in mémo.
  - **QR code** : `GET /api/qr?data=` → SVG (lib `qrcode` ajoutée à `requirements.txt`, pure Python). Bouton ▦ sur chaque lien/accès → pop-in QR (fond blanc) + récap cible/droits/PIN/personnes.
  - **Carte** : `boardMapPoints()` utilise désormais le même filtrage que la liste (recherche + filtre + projet) → plus de point « fantôme » d'un mémo masqué.
  - **Commentaires v2** : mentions `@`, **réponses imbriquées** (`memo_comments.parent_id`, un seul niveau, `_valid_parent_comment` aplatit les réponses de réponses), **priorité** (`memo_comments.priority` 0-3, pastille rouge/ambre/vert), **accusés de lecture** (table `comment_seen`, marqué auto à l'ouverture — owner « Fabien », invité = nom/email ; endpoints `POST /api/memos/<id>/comments/seen` et `POST /share/<t>/memo/<id>/seen` ; affichage « 👁 vu par … » en excluant soi-même).
- **Juin 2026 — thème clair/sombre, sidebar repliable, pop-ins partout, fix formulaire invité** (UI/UX uniquement — **aucun changement du format d'export**, toujours v15) :
  - **Thème clair / sombre** : palette claire sous `:root[data-theme="light"]` (surcharge des tokens + des surfaces à rgba sombre en dur : header / sidebar / panneau mémos / cards), bouton 🌙/☀️ dans le header (`#theme-btn`), persisté `localStorage` clé `theme`, script inline dans le `<head>` pour l'appliquer **avant le rendu** (anti-FOUC). Présent sur `index.html` ET `share.html`. Sombre par défaut.
  - **Sidebar repliable** (réalisé via le skill `emil-design-eng`, branche `ui-modernization-gsap`) : 👁 `#sidebar-eye-btn` masque toute la sidebar (classe `sb-hidden`, largeur→0, icône → `#ic-eye-off`) ; ☰ `#sidebar-rail-btn` la replie en rail d'icônes 64px (classe `sb-rail`, `overflow:hidden` pour éviter le débordement des pastilles). Indépendants, persistés `localStorage` `sbHidden`/`sbRail`, animations GSAP backIn/backOut (sur le `nav`, jamais sur un `<dialog>` — invariant 8).

  - **Fix formulaire d'accès invité** (`share.html`, `renderGuestBanner()`) : le refresh auto (`setInterval(load, 15000)`) reconstruisait le formulaire à chaque tick et **effaçait la saisie** (prénom/e-mail/code). Mauvais PIN → erreur **inline** (`#guest-error`) au lieu d'un `alert()`, **sans vider** prénom/e-mail (seul le code est remis à zéro + refocus). Validation à la touche Entrée.
- **Juin 2026 — passe responsive mobile** (UI/UX uniquement, `index.html` + `share.html`, **aucun changement d'export**, toujours v15) :
  - **Barre de projets/catégories collante** en mobile (`@media max-width:900px`) : la sidebar repliée en rangée horizontale devient `position: sticky` épinglée sous le header. Le header se replie sur plusieurs lignes (hauteur variable) → mesurée en JS dans `syncHeaderHeight()` qui pose `--header-h` (sur load, resize, ET à chaque `renderAll()`/`render()` car le bouton « + Ajouter » masqué hors vue Liens change la hauteur du header).
  - **Bouton « + Ajouter » du header masqué hors vue Liens** (`renderAll()` : `add-link` en `display:none` si `state.view !== 'links'`) — il ne crée que des liens, les vues Mémos/Projet ont leur propre barre d'ajout.
  - **Bouton ✎ Modifier** ajouté dans l'en-tête du projet (`renderBoard`, à côté de Partager) → `openCreateDialog('project', proj)`. Le double-clic/clic droit sur la sidebar reste, mais est inutilisable au tactile.
  - **Mémos en mobile** : badges (échéance, @assignés, projet, lieu) passés sur leur **propre ligne** sous le texte (`flex-wrap` sur `.task-row`, contenu `flex:1 1 100%`, badges `flex-basis:100%`) — sinon la colonne de texte s'effondre à 1 caractère/ligne. Idem commentaires (`.comment-row .c-body` pleine largeur — `!important` côté `share.html` car le `flex:1` y est en style inline) et vue Partages (`.guest-row`/`.rev-row`/`.share-row` en `flex-wrap`, `.grow` en `flex-basis:100%`).
  - **Actions de card révélées par largeur d'écran** (`@media max-width:900px { .card .actions, .task .task-actions { opacity:1 } }`) et **pas seulement** par `@media (pointer:coarse)` — le mode responsive DevTools rapporte un pointeur « fin » et le survol n'existe pas au doigt. **Dupliquer** (classe `.tdup`) masqué sur la card en mobile (trop facile à toucher ; reste dans le menu ⋯ de l'éditeur). Flèche d'expansion agrandie (`1.3rem`).
  - **Boutons ronds & barre Quill** : la règle tactile `@media (pointer:coarse) { button { min-height:44px } }` étirait les boutons ronds en **ovale** (`.task-check`, `.thumb-del`) et gonflait chaque bouton de la barre Quill (barre à 354px, icônes SVG à 38px). Fix : `min-height:0` + dimensions carrées explicites sur ces éléments. Barre d'outils Quill en mobile : **une ligne défilable** (`white-space:nowrap; overflow-x:auto` + `.ql-formats { display:inline-block }`) au lieu de s'enrouler.
  - ⚠️ **Gotcha cascade** : les media queries n'augmentent PAS la spécificité. Un override mobile placé **avant** la règle de base dans le fichier perd à spécificité égale. → Tous les overrides de mise en page mobile doivent être placés **après** les règles de base (bloc « Overrides mémos mobile » en fin de `<style>`), sinon ils sont silencieusement écrasés.

Bouton ✎ dans l'en-tête de chaque invité de la vue 🔗 Partages (édition inline). **Non destructif et cosmétique** : ne touche ni e-mail, ni PIN (sur le lien), ni token, ni `guest_token`, ni statut → la connexion de l'invité est inchangée et sa session reste valide.
