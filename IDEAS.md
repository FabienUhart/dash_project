### 🐛 [CARD-MENU-ZORDER] — le menu ⋯ d'une card passe SOUS la card suivante (correctif) → cible V27.21.z

**Statut** : bug repéré par Fabien (1ᵉʳ août 2026, capture board « IDEE ») ; cause analysée en session Cowork, brief prêt pour Claude Code.

**Symptôme** : menu ⋯ ouvert sur une card mémo (Déplacer / Partager / Dupliquer / Supprimer), la souris descend vers « Supprimer » → le menu passe tantôt devant, tantôt derrière la card suivante (clignote), les entrées du bas sont masquées.

**Cause (analysée, à confirmer en vrai)** : `.card-menu` (z-index 6) est un **enfant de la card**. Or `.task:hover { transform: translate(2px,-2px); will-change: transform }` + `transition transform 0.15s` font de chaque card survolée (ou en fin de transition, 150 ms) un **stacking context** temporaire → quand la card du menu ET la card suivante en sont deux **en même temps** (survol qui bascule en descendant dans le menu, transitions qui se chevauchent), l'ordre DOM l'emporte et la card suivante peint **par-dessus** le menu (son z-index 6 est confiné dans le contexte de sa card). Le décalage `translate(2px,-2px)` déplace en plus le menu sous le curseur → oscillation du hover.

**Correctif attendu** : à l'**ouverture** d'un menu, poser une classe sur la card porteuse — `.task.menu-open { position: relative; z-index: 7; }` + `.task.menu-open, .task.menu-open:hover { transform: none; }` (stoppe le décalage 2px) — retirée à la **fermeture** partout (re-clic ⋯, clic sur une entrée, closer global au clic extérieur index ~6428 / share ~3589) ; le plus sûr : un helper `toggleCardMenu(menu)` qui synchronise `hidden` + la classe. **Portée** : les 3 menus `.task-more` — card mémo owner (index ~7121), menu votes (index ~6710), card mémo share (share ~3394) ; hub non concerné (pas de `.task-more`). Au passage, **vérifier share.html** : la règle de base `.card-menu { position:absolute; top:…; z-index:6 }` n'existe que dans index.html — la rapatrier en style partagé si le menu share est en flux. Frontend pur, **export inchangé (v27)**. Invariants 8/9 (zéro GSAP, tokens seulement).

**Acceptation (validation Cowork)** : owner, 2 cards empilées → le menu du 1er reste DEVANT la 2e sur tout le trajet souris jusqu'à « Supprimer », sans clignotement ; idem share (invité éditeur) ; menu votes OK ; en-têtes sticky du board OK au scroll menu ouvert (sinon : fermer le menu au scroll, plutôt que monter le z-index) ; mobile ≤ 900 inchangé. `node --check`.
